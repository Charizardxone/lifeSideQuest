## 一、先看结论

你已经具备 Node.js 开发环境，本次检查也确认 pnpm 和 Git 可运行。下一步最重要的是准备开发数据库、初始化工程，并在相关功能开发前确定关键业务规则。

**不需要把所有清单完成后才能开工。**数据库准备期间，可以先搭建用户端、共享类型和页面骨架；后端连接与联调需要数据库就绪。

清单中的“开发执行”表示后续可以交给开发者或 Codex 处理，并不要求你手工完成。本次仅检查环境和编写文档，没有安装软件、创建数据库或初始化工程。

## 三、开工必需：环境与工程

### 3.1 开发数据库

PostgreSQL 保存公开任务、版本、每日排期、运营账号和匿名统计。用户个人经历仍按技术方案保存在浏览器本地，两者用途不同。

**建议：已有 PostgreSQL 就复用实例并创建独立开发库；没有的话，可在 Windows 本机安装。Docker 是可选的另一种运行方式。**

| 方式 | 适用情况 | 需要准备 |
|---|---|---|
| 本机 PostgreSQL | 当前单机开发，希望直接运行 | 数据库服务、独立开发库及专用账号 |
| Docker 运行 PostgreSQL | 已熟悉容器或希望团队环境一致 | 可运行的 Docker、固定镜像版本、持久化数据卷 |
| 远程开发数据库 | 已有可用资源或需要多人协作 | 专用开发库、连接权限、网络及 TLS 配置 |

- [ ] 确定采用哪一种数据库运行方式。负责人：你确认，开发执行。
- [ ] 准备独立数据库，例如 `sidequest_dev`，以及仅用于该库的开发账号。负责人：开发执行。
- [ ] 将连接信息写入后端本地环境文件，使用 `DATABASE_URL`。负责人：开发执行。
- [ ] 验证 Payload 能连接、执行初始迁移，并在重启后读到已有数据。负责人：开发执行。
- [ ] 如果采用容器，确认数据位于持久化卷，明确如何启动和停止。负责人：开发执行。

验收结果：后端可以创建并读取一条测试任务，数据库重启后记录仍存在。不要将开发迁移指向生产数据库。数据库密码不需要粘贴到聊天或提交进仓库。

### 3.2 工程初始化

- [ ] 初始化 Git，设置 `.gitignore`，排除依赖、构建产物、真实环境文件和数据库数据。负责人：开发执行。
- [ ] 检查 Git 提交姓名与邮箱；已有正确配置可沿用。负责人：开发执行，缺失时你提供。
- [ ] 创建 `apps/web`、`apps/content`、`packages/domain`、`packages/contracts`。负责人：开发执行。
- [ ] 固定 Node.js 与 pnpm 版本，配置 pnpm workspace 和依赖锁文件。负责人：开发执行。
- [ ] 创建 React / Vite 用户端和 Payload / Next.js 内容端。负责人：开发执行。
- [ ] 配置 TypeScript、ESLint、Prettier、Vitest 和必要测试目录。负责人：开发执行。
- [ ] 提供统一启动、构建、类型检查、测试和数据库迁移命令。负责人：开发执行。
- [ ] 更新 README 与 AGENTS.md，写明实际可用命令。负责人：开发执行。

框架是项目依赖，无需你提前全局安装 React、Next.js 或 Payload。远程 Git 仓库不是本地开工前提，可在工程初始化后创建并推送备份。

### 3.3 配置与后台账号

- [ ] 提供 `.env.example`，只写变量名和占位值。负责人：开发执行。
- [ ] 配置 `DATABASE_URL` 和随机生成的 `PAYLOAD_SECRET`。负责人：开发执行。
- [ ] 约定开发地址，例如用户端 `http://localhost:5173`，后台 `http://localhost:3000/admin`，实际端口以配置为准。负责人：开发执行。
- [ ] 配置用户端公开 API 地址、后台来源白名单和跨域设置。负责人：开发执行。
- [ ] 创建首个开发管理员并验证登录、退出。负责人：你选择账号，开发执行初始化。
- [ ] 创建编辑角色或测试账号，验证不能越权发布、管理账号。负责人：开发执行。

验收结果：两个应用能启动，后台能登录，用户端能读取公开接口，未登录不能访问草稿或执行管理操作。配置中的服务端密钥不能进入用户端构建产物。

## 四、相关功能开工前：业务规则

以下项目可以边搭工程边确认，不阻塞页面骨架；建议值不代表已经决定。决定后写回需求和技术文档，并作为测试依据。

| 勾选 | 需要确定的内容 | 当前方案或建议 | 最迟完成时间 |
|---|---|---|---|
| [ ] | 进行中数量上限 | 沿用需求建议的 5 条 | 开发接取功能前 |
| [ ] | 撤销完成时间窗口 | 技术方案未定具体时长 | 开发撤销和奖励事务前 |
| [ ] | 重复任务奖励 | 默认只奖励一次；允许重复的任务可继续记录、后续零奖励 | 冻结奖励规则前 |
| [ ] | 今日与普通入口奖励关系 | 明确同一任务是否共享奖励限制 | 开发今日奖励前 |
| [ ] | 跨日完成 | 明确昨日接取、今日完成是否获得每日奖励 | 开发今日支线前 |
| [ ] | 等级阈值及属性分配 | 固定起始等级、整数阈值，解决示例与 70% 属性上限的矛盾 | 开发角色卡和导入任务前 |
| [ ] | 随机池耗尽 | 建议提示用户开启新一轮 | 开发随机功能前 |
| [ ] | 本地照片与存档 | 沿用首版本地保存方案，明确不提供云恢复 | 开发存档前 |
| [ ] | 图片规格 | 确定允许格式、输入上限和压缩目标 | 开发照片选择前 |
| [ ] | 离线任务缓存 | 建议 24 小时有效期；过期停止新推荐和接取 | 开发离线策略前 |
| [ ] | 匿名统计 | 确定留存期、告知文案和远端删除范围 | 接入正式统计前 |

对这些规则可由开发先提交具体默认值和例子供你确认，不需要你先设计完整算法。任务编号和依赖见技术文档第八章。

## 五、页面与内容准备

### 5.1 最小页面方案

- [ ] 确定基础视觉方向：颜色、字体、卡片样式和按钮层级。负责人：你定偏好，开发提供初稿。
- [ ] 准备首页、任务详情、我的支线、完成反馈、存档、角色卡、设置的简单线框。负责人：开发执行。
- [ ] 覆盖加载、空列表、保存失败、断网、缓存过期和容量不足状态。负责人：开发执行。
- [ ] 明确本地数据说明、清除确认和导出提示的文案。负责人：开发起草，你确认。
- [ ] 先沿用 Payload 基础后台界面，单独梳理任务预览、排期和统计的定制页面。负责人：开发执行。

不要求先完成整套高保真设计。图标和品牌名称可先用占位，正式图标在 PWA 安装测试前补齐。

### 5.2 开发种子任务

- [ ] 先准备建议 12–18 条测试任务，覆盖六个类别。负责人：开发整理，你审阅。
- [ ] 覆盖不同时间、预算、同行方式、奖励和重复策略。负责人：开发执行。
- [ ] 准备草稿、下架、字段错误等测试样例，明确它们不能公开发布。负责人：开发执行。
- [ ] 每条有效任务包含标题、步骤、标签、注意事项、奖励和版本信息。负责人：开发执行。
- [ ] 通过共享字段校验，形成可重复导入的种子数据。负责人：开发执行。

12–18 条是开发联调样本，不替代需求中的 60 条内容原型、首发不少于 120 条任务、30 条内部试玩和未来 14 天排期要求。首发内容可与开发并行准备。

## 六、联调与测试准备

- [ ] 使用可打开开发者工具的桌面浏览器进行日常调试。负责人：开发执行。
- [ ] 端到端测试开始前下载 Playwright 所需浏览器。负责人：开发执行。
- [ ] 准备至少一台实际手机验证页面和微信内置浏览器；覆盖条件不足时记录限制。负责人：你提供设备，开发组织用例。
- [ ] 配置移动设备测试地址，确认电脑和手机能访问服务。负责人：开发执行。
- [ ] 进行 Service Worker / PWA 测试时提供受信任的 HTTPS 测试地址。负责人：开发执行。
- [ ] 建立 AC 01–10 测试记录，尤其覆盖重复点击、多标签页、撤销、午夜切换和断网。负责人：开发执行。
- [ ] 准备一次导出、一次确认删除、一次数据库版本升级的测试数据。负责人：开发执行。

电脑上的 `localhost` 可以作为本地可信来源，但手机通过电脑局域网 IP 的普通 HTTP 地址访问，不具有同样的安全上下文条件。普通页面可先联调，PWA 能力需要单独验证。[MDN 安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts)

## 七、可以推迟到上线前的准备

这些项目不阻塞本地开发，也不需要现在就采购。

- [ ] 正式域名与固定用户端来源地址；本地记录按站点来源隔离，换域名需要处理迁移或导出。
- [ ] 用户端静态托管、Node.js 内容服务和生产 PostgreSQL 的部署环境。
- [ ] HTTPS、正式管理员、生产密钥、数据库备份和恢复验证。
- [ ] 远程代码仓库、持续检查与发布流程。
- [ ] 实际目标网络的访问测试、错误日志、排期缺口和备份失败提示。
- [ ] 隐私说明、个人数据管理说明和匿名统计告知。
- [ ] 正式任务库、安全复核、试玩记录和每日排期。
- [ ] 根据实际部署地区确认上线所需手续和服务条件。

首版本地照片不需要购买对象存储；管理员本地登录可先不接邮件服务，但公开上线前应明确账号恢复方式。原生应用商店账号、AI 服务密钥、短信登录和支付服务均不属于当前 MVP 准备项。

## 八、建议执行顺序与开工验收

| 顺序 | 动作 | 可以继续的工作 |
|---|---|---|
| 1 | 确定 PostgreSQL 来源，检查连接条件 | 同时搭建工作区和用户端骨架 |
| 2 | 初始化 Git、依赖、Payload 和环境配置 | 后台登录及数据库联调 |
| 3 | 冻结任务字段和关键奖励规则，准备种子内容 | 开发随机、接取和完成闭环 |
| 4 | 完成基础页面方案和个人数据提示 | 开发存档、角色卡与设置 |
| 5 | 补齐发布、排期、统计和离线测试 | 进入完整 MVP 验收 |

**工程准备完成的判断标准：**

- [ ] 新终端按 README 可以启动用户端和后台。
- [ ] 后台连接 PostgreSQL，管理员可以登录。
- [ ] 一条合法测试任务可以保存，并经公开接口读取。
- [ ] 草稿和后台管理写操作有权限限制。
- [ ] 构建、类型检查和基础测试可运行。
- [ ] 仓库不包含真实密码，环境样例可供他人复现。

达到这些条件即可进入技术文档中的模块开发，无需等待域名、云服务器或完整首发内容库。
