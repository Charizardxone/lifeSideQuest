# 私人 ZIP 备份替换导入

## 用户确认与实现

用户明确选择：**导入备份并替换现有个人记录**。本次没有实现合并导入。

入口：设置 → 个人数据 → 导入私人存档。选择文件仅进行读取、校验与预览，显示导出时间以及当前/备份的任务、完成存档、照片、想做数量和经验。用户勾选替换确认后才能执行；取消不改变数据。空备份也会替换当前数据，必须同样明确确认。

沿用现有 schemaVersion 1 ZIP 格式，包括 data.json、README.txt 与 photos/*.jpg，因此此前导出的备份可导入。新导出包的 README 更新为当前操作说明。文件只在当前浏览器处理，不上传到 Payload 或其他服务。

核心实现：

- `packages/contracts/src/archive.ts`：严格校验版本、结构、字段、任务快照与图片元数据。
- `apps/web/src/services/import.ts`：限制解压体积、校验唯一标识/关联/状态/奖励/领奖记录，准备只读预览，事务中替换个人数据。
- `apps/web/src/app/archive-import.tsx`：文件选择、预览、明确确认、取消、错误反馈与成功后的刷新提示。

ZIP 最大 64MB，解压合计 128MB，data.json 最大 16MB，最多 10,002 个文件；单张 JPEG 最大 1MB、最长边 1920px。拒绝未知/重复文件、路径异常、无效版本、照片缺失、图片解码失败、重复执行/存档、关联断裂、名额超限、错误奖励、重复今日领奖和不完整重复次数历史。历史奖励按快照和已保存次数校验，恢复流水，不调用完成发奖流程。

确认时在单个 Dexie 读写事务内重新检查当前身份及预览后数据是否变化；校验通过后清理并恢复个人表，失败整批回滚。公共 catalog/daily 缓存不清除。新匿名身份使旧标签页无法继续写入，所有导入的归属字段映射到新身份。旧的每日进行中任务按北京时间过期，已知安全下架的进行中任务自动放弃，补记对应本地事件，不发奖励。

## 边界

- 本功能是手动替换恢复，不合并、不做云备份或自动跨设备同步。只有用户保管的 ZIP 才能用于恢复，未备份的数据无法找回。
- 备份可以在另一浏览器中手动导入；公开内容仍由当前配置的 Payload 服务提供。离线可读取已恢复的存档与执行，但缺少有效公共缓存时不能新接取。
- 预览后若本地个人记录有变化，会停止导入，需重新选取备份生成预览。导入前建议先导出当前数据；确认替换将丢弃备份中没有的个人内容。
- 本次不重复尝试此前缺少系统依赖的 WebKit，未宣称通过 Safari/真机验收。浏览器图片解码校验通过 Chromium 验证；fake-indexeddb 单元环境校验元数据及 JPEG 标记，不模拟浏览器图片解码器。
