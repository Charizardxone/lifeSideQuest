## 执行方式

数据源：[starter-quests.ts](../../apps/content/scripts/data/starter-quests.ts)。一次性脚本：[seed-starter-quests.ts](../../apps/content/scripts/seed-starter-quests.ts)。脚本不在应用启动时执行，不输出数据库密码。

```sh
# 只读检查：字段、50 条唯一标题、现有数据库重名、批次标记。
pnpm --filter @sidequest/content exec payload run scripts/seed-starter-quests.ts

# 在真实事务中验证完整发布流程，随后回滚，不保留测试内容。
SIDEQUEST_SEED_MODE=verify pnpm --filter @sidequest/content exec payload run scripts/seed-starter-quests.ts

# 本批用户已明确授权；事务性创建草稿、复核并发布。
SIDEQUEST_SEED_MODE=apply pnpm --filter @sidequest/content exec payload run scripts/seed-starter-quests.ts
```

使用现有唯一管理员作为审计执行身份；存在多个管理员时脚本停止，不自行选择。复核勾选用于执行本次用户授权发布，任务 reason 字段说明自动文案/结构检查与未实地试玩边界，不声称管理员亲自试玩。

同一事务写入 50 条任务、50 个不可变版本、150 条任务工作流审计和 1 条批次审计；任意写入失败整批回滚。回滚验证可能消耗 PostgreSQL 自增序列号，这是正常现象。批次唯一键防止并发重复导入；已导入则只读返回，不覆盖后续编辑、不重新发布已下架任务。已有同名条目会阻止新批次写入，而非静默覆盖。

批次键：`content-seed:2026-09-15:starter-50:v1`。内容摘要和实际任务 ID 保存在批次审计的 entityId JSON 中。
