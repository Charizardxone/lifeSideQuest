# T04 单任务状态规则验证

日期：2026-09-15。依据：用户明确确认的 D03、D11 上限部分、D14 关闭结论；关联 FR 031、FR 032、FR 040、FR 071 和修订后的 AC 04。

## 实现

- contracts 导出固定上限 `ACTIVE_QUEST_LIMIT = 1`，执行状态为 `in_progress` / `completed` / `abandoned`，动作仅有 `complete` / `abandon`。
- domain 的 `assertCanAcceptQuest` 要求当前全来源进行中数量为 0；已有一条或异常多条时拒绝新接取。
- `transitionUserQuest` 仅允许进行中完成或放弃；已结束执行不可重开，重复完成/放弃和撤销等非法动作均返回明确错误。
- 相同 operationId 的重试应由后续事务服务先返回已保存的结果，再决定是否调用状态转换；纯状态机本身不重发奖励。
- 已放弃后重新接取要创建新的执行记录；完成或放弃事务提交后才能释放名额。此处只定义规则，尚未实现数据库操作。

## 验证

新增 19 项测试，覆盖空名额、有进行中任务、异常计数、两种合法终态、终态不可修改、未定义动作及非法持久化状态。当前 `pnpm test` 共 70 项通过；全工作区类型检查、ESLint、contracts/domain 构建、Prettier 和差异空白检查均通过。

本次同步需求 V1.3、架构 V0.4 和任务文档；AC 04 保留编号并改写场景。移除计划中的撤销窗口、反向奖励流水、撤销统计事件和超限恢复策略；保留未成功提交时的原子事务回滚。
