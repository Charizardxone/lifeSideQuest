## 范围与使用方式

保留架构文档的 M01–M12、T01–T25 编号，每个模块一份任务文档。全部属于 MVP P0；优先级不代表开工顺序。具体实现与验证状态以模块文档为准，业务接口仍为计划交付。后端已确认使用 Payload CMS、TypeScript、Node.js / Next.js；其他技术沿用架构基线，初始化时核验兼容版本。

匿名首次使用、一键随机、默认私密和分析数据最小化为共同约束。账号、云同步、分享卡、参与人数、AI 推荐和社交不进入本轮。存在产品空白或文档冲突时，先查[决策清单](./00-规则确认与决策清单.md)，不可把建议值直接当作最终验收规则。

每个 T 编号可以作为一个开发 issue；内部清单可进一步拆成提交。执行时在对应任务下记录负责人、状态（未开始/进行中/待决策/待验收/已完成）、实现链接和验证记录。仅相关子项等待决策，其余独立工作可继续。

## 里程碑与依赖

| 阶段 | 进入条件 | 退出条件 |
|---|---|---|
| S0 工程与契约 | 阅读需求和决策清单 | T01–T04 完成；核心规则已记录确认结论，契约可供双方实现 |
| S1 本地闭环 | T03 契约和相应规则可用 | T05、T06、T11–T17 完成；种子 catalog 支撑随机→接取→完成→存档→成长，浏览器重启数据仍在 |
| S2 运营接入 | 契约可用，内容端及本地端可分别开发 | T07–T10、T18、T19、T22、T23 完成；真实发布、下架、今日排期与指标打通 |
| S3 发布 | S1、S2 联调完成 | T20、T21、T24、T25 通过；发布证据齐全 |

模块内列出更细的依赖。T11 的种子数据适配器遵守 T03 的 catalog 契约，因此 S1 不必等待 T10；正式验收必须接入 T10。T06 提供通用事务机制，T12/T14 实现业务操作。T22 只保存本地事件，首版不接入网络上报。T18 的排期后台不依赖 T14，T19 的领取闭环依赖 T14。

不在缺少人员与可用工时信息时承诺日历排期；按上述退出条件推进。内容编写和真实试玩应在 S0 后开始，最终归 T25 验收，不能到发布前才准备。

## 统一完成定义

- 实现对应任务清单，关联 FR/AC，无超出 MVP 的能力。
- 必要的规则、事务、权限和异常用例通过；UI 任务附移动端与桌面截图。
- 配置、接口、数据库迁移和运行命令同步文档；真实密钥不入仓库。
- 记录验证环境、命令、结果和限制；未运行的测试不能标为通过。
- 所依赖的决策已确认，或明确标记仅完成不受影响部分；负责人完成复核后更新状态。
